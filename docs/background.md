# SnapBug 项目需求背景

## 1. 项目概述

- **项目名称**：SnapBug
- **一句话定位**：一款面向中小型研发与测试团队的**轻量级研发协作与缺陷追踪工作台**，定位为传统重型工具（如禅道）的极简现代替代方案。

---

## 2. 需求背景与痛点

在实际研发与测试协作过程中，禅道等传统研发管理工具普遍存在明显的使用阻力：

1. **流程过重、层级套娃**：强绑定“产品 → 项目 → 执行 → 需求 → 用例 → Bug”等复杂层级，小型或敏捷团队维护成本极高。
2. **表单冗长、提单繁琐**：提交一个 Bug 需要填写大量低价值必填字段，操作路径长，严重影响测试与研发的反馈意愿。
3. **界面陈旧、体验割裂**：信息密密麻麻、视觉压抑，缺乏现代 Web 应用的流畅交互体验。
4. **沟通成本高、描述不规范**：口语化、缺要素的缺陷描述频发，导致研发排查时反复追问复现步骤与预期结果。
5. **个人工作分散**：除了修 Bug，研发日常还涉及排查笔记、工作计划与周报整理，在不同工具间频繁切换效率低下。

**核心诉求**：摆脱禅道这类繁琐难用的重型系统，构建一个**清爽、轻量、高频操作一步直达**，并结合 AI 提效的研发工作台。

---

## 3. 产品核心理念

- **去繁就简**：砍掉冗余流程与非必要表单，聚焦研发与测试真正每天都在用的高频动作。
- **清爽直观**：采用现代、轻盈的界面风格与交互方式（Bento 工作台、列表/卡片双视图、右侧抽屉详情、快捷键直达）。
- **AI 辅助增效**：在最耗精力的文字整理环节引入 AI（如口语化 Bug 描述一键重构为标准复现步骤、笔记要点提炼等），提升协作质量。
- **协作与个人空间合一**：将团队缺陷追踪与个人日常（笔记、工作计划、周报）整合在一个轻量工作台中，形成闭环。

---

## 4. 目标用户

主要面向中小型软件研发团队的日常协作角色：

- **测试工程师**：快速提报缺陷、借助 AI 规范描述、跟进验证与关闭。
- **前端 / 后端开发**：登录后直达“指派给我的”待处理单，快速流转状态、记录排查笔记与当日计划，并一键汇总周报。

---

## 5. 大致功能版图（初版方向）

基于当前静态原型规划，项目大致由以下四个核心模块构成：

1. **工作台（Dashboard）**
   - 聚合呈现本周缺陷概览与流转趋势、今日工作计划时间轴、高频快捷操作、个人笔记速览以及指派给我的最新 Bug。
2. **Bug 追踪（核心模块）**
   - 极简快速提单（支持快捷键唤起），内置 **AI 一键优化**，将随手输入重构为规范的「问题描述 / 复现步骤 / 预期结果 / 实际结果」。
   - 支持「指派给我的 / 我提交的 / 团队全部」视角切换、关键词与状态筛选，以及**列表 / 卡片**双视图自由切换。
   - 轻量状态流转（待处理 → 处理中 → 待验证 → 已关闭），支持右侧抽屉查看详情、评论记录及站内消息通知。
3. **个人笔记**
   - 用于记录问题排查思路、脚本、接口避坑指南与架构思考，支持自动保存及 **AI 提炼要点**。
4. **工作计划与周报**
   - 轻量级日程/任务清单与完成进度追踪，联动本周已完成计划与处理中的 Bug，支持**一键生成周报**。
